LATEST FIX - HISTORY 500 / KeyError: 0
---------------------------------------
Root cause: database.py get_stats() used fetchone()[0]. The application configures
psycopg with dict_row for PostgreSQL/Neon, so PostgreSQL returns named fields and
row[0] raises KeyError: 0.

Fix: get_stats() now uses explicit SQL aliases and named-column access for total,
critical, warnings and incidents. This is compatible with both PostgreSQL/Neon
and SQLite (sqlite3.Row). A regression test now simulates PostgreSQL dict_row
responses and verifies all four statistics.
